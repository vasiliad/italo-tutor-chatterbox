## 2. Грабли Gemini Live API и обходы (3.1-flash-live-preview)

### 2.1 Модальность и «немые» ответы
- **TEXT-модальность 3.1 не поддерживает: сервер закрывает с 1007.** Любой текстовый ответ (план, силлабус,
  судья, резюме, вердикт) берётся так: `response_modalities=["AUDIO"]` + `output_audio_transcription`,
  результат — транскрипт речи. Из этого два следствия. Построчный формат ответа судьи идёт через речь
  и искажается (так и написано в разборе «творческой домашки»). Каждый такой вызов стоит озвучки.
- **`thinking_config` не ставить.** Источник — A/B-тест `mute_ab_test.py` от 27.08: при
  `thinking_level="low"` и текстовом входе примерно 2/3 ответов приходят без аудио, только с транскриптом.
  Дефолт (minimal) чистый.
- **MuteHeal.** Даже без thinking preview-модель иногда присылает ход с текстом, но без звука
  (1–2 раза за урок, на уровне вав до 6). Лечение: после `turn_complete`, если в ходе был `ModelText`
  без `AudioOut`, отправить «Твой прошлый ответ пришёл без звука. Повтори его голосом, пожалуйста, не
  упоминая этот сбой.» Не больше **2 раз подряд**; ход со звуком сбрасывает счётчик; прерванный ход не
  лечится. Ошибка отправки при лечении валит сессию (она уходит в Closed).
- В OneShot немой ход **повторяется** (`SILENT_RETRIES`), а пустой транскрипт считается «пустой ответ».

### 2.2 Жизнь сессии, goAway, resumption, коды закрытия
- **~10 минут на сессию.** Замер на шести уровнях: `goAway` приходит на **540-й секунде** с
  `time_left=50s`. Если сессию не закрыть самим, сервер закрывает её с **1008** (у алефа — на 591-й с).
  Урок это переживает через resumption, но с «швом».
- **Мягкий рефреш**, как сделано у Хавы: после `goAway` закрываем сами. Если модель простаивает (буфер
  транскрипта пуст и после хода аудио нет) — сразу; иначе после хода, «не позже чем через N с» (дедлайн
  внутри `time_left`). Нельзя закрывать сразу после отправки служебного сообщения и пока ученик говорит.
  Есть ticker-гвард «time_left истекает». Итог: бет…вав закрылись сами через 2–24 с после goAway,
  `resume=да`, **1008 ни разу**. В 70-минутном уроке было 7 рефрешей (каждые ~9,5 мин) и 0 обрывов.
- **Брифинг после рефреша по хендлу — КОРОТКИЙ** (`_briefing_short`: «СВЯЗЬ ОБНОВЛЕНА (плановый рефреш)
  — продолжай» + ВРЕМЯ + состояние дрилла). Контекст на сервере цел, а длинный текст Хава **зачитывает
  вслух**: 4 эха ЦЕЛЬ/ОШИБКИ/ПЛАН/ВРЕМЯ за урок, после правки 0.
- **Полный брифинг — только при потере контекста** («СВЯЗЬ ПРЕРЫВАЛАСЬ — продолжай»: план, резюме,
  ошибки, 8 последних реплик, дрилл, строка ВРЕМЯ, «НЕ здоровайся заново, не представляйся, связь не
  обсуждай, служебный текст не повторяй»). Брифинг **отложенный**: текстом он уходит склейкой с репликой
  ученика («Новая реплика ученика: …»), голосом — в момент первой `input_transcription`. Сразу — только
  если последняя строка истории — реплика ученика без ответа (тогда «ответь на неё прямо сейчас»,
  максимум один ход). Иначе получается цикл «реконнект → брифинг → ход → обрыв».
- **Контекст после реконнекта без хендла модель не помнит.** В OneShot продолжение делается так: промпт
  целиком + «(Ты уже начала отвечать, но связь прервалась. Вот конец уже сказанного: «…». Продолжи РОВНО с
  этого места…)», до 3 раундов, общий дедлайн 120 с, раунд 75 с.
- **Хендл отвергнут** (`resume_rejected`: подстроки resum/handle + invalid/expired/reject) → сбросить
  хендл, открыть новую сессию, восстановить контекст по своей записи.
- Главная находка 06.09 (CLAUDE.md, факт 8). У Python-SDK `AsyncSession.receive()` **завершается
  после каждого `turn_complete`**. 1.0 принимал это за обрыв и переподключался после КАЖДОГО хода:
  «обрывы ~9 с», потеря памяти, повторные приветствия. Эти «обрывы сети» программа устраивала себе сама.
  В 2.0 `receive()` вызывается в цикле. Нам (сырой WebSocket) это не грозит, но вывод общий: частые
  «обрывы» сначала ищи у себя.
- Отдельного 15-минутного лимита не видно (уроки по 16 мин, 70 мин), но у Хавы **всегда включено
  `context_window_compression=sliding_window`**.
- Коды и причины (`errors.py`, google-genai 2.x). Код закрытия WS пробрасывается как `APIError.code`:
  - **1007 «location is not supported»** → блокировка по региону (`region_blocked`). Тот же 1007
    приходит на TEXT-модальность, на поток кадров `realtime_input(media=…)` и на PDF-вложение.
    **Различать по тексту причины.**
  - 1006 / таймаут / connection reset → `net_abnormal` (сеть). 1000/1001 → чистое закрытие
    (сервер/GoAway): это **не свойство сетевого пути, узел VPN из-за него не менять** (иначе узлы
    переключаются туда-сюда).
  - 429 / RESOURCE_EXHAUSTED / quota → `quota` → **ротация ключа** без задержки. Если исчерпаны все
    ключи — «Лимиты всех ключей исчерпаны — жду N с».
  - 401/403 / UNAUTHENTICATED / PERMISSION_DENIED / «api key not valid» → `auth` → другой ключ.
  - 404 / NOT_FOUND → «Модель недоступна — обновите программу», повтор через `MODEL_GONE_RETRY_S=60`.
  - FAILED_PRECONDITION со словом location → регион.
  - На рукопожатии: `InvalidStatus` (HTTP 4xx/5xx от прокси), «timed out during opening handshake»,
    gaierror/SSLError. `ExceptionGroup` разворачивать.
  - Про 1011 в HANDOFF и в коде нет ничего; отдельной ветки для него нет, он уходит в `other`.
- REST-проба перед WS: **HTTP 400 с «location»/«not supported»/FAILED_PRECONDITION = регион**.
  Раньше такой 400 считали «пускают», и блок вскрывался только 1007 внутри цикла. Регресс 1.0:
  **17 × 1007 за 62 с** — вечный цикл «выбрать узел → None → 1007».

### 2.3 VAD, пауза, транскрипции
- `realtime_input_config.automatic_activity_detection`: `end_of_speech_sensitivity=END_SENSITIVITY_LOW`,
  **`silence_duration_ms=2500`** (было 800). Основание — литература по тьюторингу 1:1: пауза ≥3 с после
  реплики ученика удлиняет его ответы в 4–8 раз. Вынесено в настройку «Пауза после вашей реплики».
- **Серверному VAD нужен непрерывный поток звука.** Если между репликами поток прерывается, сервер не видит
  конца речи: в голосовой симуляции четыре реплики склеились в одну. Лечится «насосом тишины» — нули в
  паузах. В OneShot-судье к записи ученика добавляется хвост тишины (`SILENCE_TAIL_S=0.8`,
  `HW_TAIL_SILENCE_S=1.2`) и ставится VAD 400 мс, чтобы авто-VAD закрыл ход.
- **Транскрипт ученика запаздывает на секунды** — темп по нему не мерить (см. §2.8).
- **Ошибки ученика берутся из речи УЧИТЕЛЯ** (структурная фраза «Ошибка (тип): было …, надо …», а в свободной
  речи — исправление в любой форме, которое собирает суммаризатор). ASR ученика для этого не используется.
- `output_transcription` содержит и то, что модель **зачитала из служебного текста** (§2.6).

### 2.4 Голос
- В HANDOFF прямо сказано: «`voiceName` модель игнорирует (голос — только промптом)». Для второго
  голоса симуляции поменяли **описание голоса** в промпте: «единственный рычаг, voiceName сервер игнорирует».
  В конфиге Хавы всё равно передаётся `Kore`. На слух различие голосов не проверяли.
- Голос учителя задан в system_prompt: «warm, calm, unhurried female voice of an experienced teacher in her fifties».
- Разные роли озвучиваются **с разных ключей** (второй ключ — «побочный»: эталоны, судьи, второй голос),
  чтобы не делить квоту урока.

### 2.5 Инструменты (tool calls)
- Пробник `tools/probe_tool_call.py` (10.09): 3.1-live в аудио-сессии зовёт `board_write` 2/2,
  аргументы приходят на иврите с огласовками, после ответа инструменту модель продолжает говорить.
- **Вызов у 3.1 синхронный: пока `toolResponse` не ушёл, модель молчит.** Отвечать сразу и **всегда**,
  в том числе на неизвестный инструмент (ответом с ошибкой, «unknown tool»).
- Всё долгое (поиск картинки в сети) выполняется в фоне: сразу ответ инструменту и заглушка на доске
  «ищу картинку», потом замена. Не нашлось — урок идёт дальше.
- ⛔ **URL, придуманный моделью, не принимать**: модель описывает словами, что показать, а ищет код
  (Wikimedia Commons, с автором и лицензией).
- Декларации: у всех параметров тип STRING, `{"name","description","parameters":{type:OBJECT,properties,required}}`.
- Инструмент, который модель **ни разу не позвала сама** (`board_variants`, `board_image`), считается
  непроверенным. Счётчик `board_calls` ведётся в архиве.

### 2.6 Служебные сообщения и эхо
- Единый префикс `(служебное, не зачитывай) <ФОРМАТ>:`. Отметки ВРЕМЯ присылает **только система**.
  В 70-минутной симуляции Хава **сама «написала» строку «ВРЕМЯ: осталось 10 мин» и закруглила урок
  по ней**. После этого в первый ход и в промпт добавили: «сама их не пиши, не произноси и не придумывай».
- Эхо служебного бывает. `strip_service_echo`: всё от маркера `\(\s*служебное|\(\s*ученик написал` и
  дальше **не разбирается**. Причина — живой прогон 08.09: Хава зачитала «(служебное…) Верно засчитано…
  СТИМУЛ 5/8», харнесс нашёл в НАШЕМ тексте «Верно» и засчитал **пять ложных «верно» подряд**, а пример
  «Ошибка (тип)…» из служебного мог попасть в память ученика.
- `_cut_service_echo` (10.09) **глушит звук хода сразу**: в одном эхе вслух прозвучал ожидаемый ответ
  стимула, и дрилл превратился в чтение. Маркер стоит в начале служебного текста, поэтому звук режется
  раньше, чем дойдёт до ответа.
- **Эхо пометки письма в начале хода** («(ученик написал, не сказал)…») — это другое: скобку снимаем,
  ход разбираем, звук не режем (`strip_written_echo_head`, метрика `written_echoes`). В текстовой
  симуляции из этого вышло 181 из 187 «эхо».
- «Эхо-шторм» (бет, 187 эхо на 196 ходов, дрилл ушёл в 142 «accept»). Гипотеза — **длинный блок
  (~2000 знаков с ⛔) в первом ходе научил модель начинать каждую реплику служебной пометкой**. На ваве
  с песней было 33 настоящих служебных эха против 0–8 без песни. Метрика `service_echoes` — сигнал,
  что служебные тексты пора ужимать. В голосовом уроке эхо 0–2 против 9 за 6 мин с печатающим учеником.

### 2.7 Картинки и файлы во вход
- Пробник `tools/probe_file_input.py` (11.09). **Картинку модель видит только вложением хода**:
  `send_client_content(turns=[{role:"user", parts:[{inline_data:{data, mime_type:"image/png"}}, {text}]}],
  turn_complete=True)`. **Поток кадров `send_realtime_input(media=…)` → 1007.
  PDF вложением → 1007** — PDF превращается в текст (pypdf), скан без текстового слоя — честный отказ.
- Просьба ученика («проверь упражнение 3») едет вместе с файлом.

### 2.8 Латентность и темп
- Темп дрилла считать от **конца звука** стимула (`Speaker.played_until`), а не от `turn_complete`:
  генерация кончается раньше, колонки доигрывают ещё секунды. Иначе мгновенный ответ на длинный стимул
  шёл как «медленно», и главное правило штрафовало не того. Ответ во время звука = 0.
- Порог «быстро» `TEMPO_FAST_S=2.5`. Набранный ответ темпом не судится (`latency=None`), попытка после
  объяснения («СМЕНИ ПОДХОД») тоже (`was_explained`).
- Сеть: 3 REST-пробы при старте и раз в минуту без урока. Пороги 800/2000 мс; сессия <15 с при ≥2
  обрывах = «нестабильно». Реконнект с хендлом занимает 1–3 с «шва». **Перевыбор узла VPN во время живой
  сессии = 16–22 с мёртвого эфира**, поэтому все сетевые манёвры делаются только между сессиями.
- OneShot: `Semaphore(1)` (очередь — текстоген, судьи и силлабус не параллелятся), таймаут раунда,
  дедлайн, лог `text_gen ok|partial|fail: с, символов, раундов, причина`. Ретраи судьи умножались:
  3 внешних × 3 внутренних = до 9 живых попыток (~3–4 мин на один «недоступный» пункт) — исправлено.

### 2.9 Поведение модели как учителя (не API, но грабли того же слоя)
- **Модель рвётся закончить урок**: на 7, 21 и 34-й минуте; с идеальным учеником — 5–16 раз за час.
  Причины: не видит часов; план на одну микроцель — это 10–15 минут материала; «спасибо» ученика запускает
  прощание. Лечение: часы служебными сообщениями (каждые 10 мин и **только в простое** — модель не
  посреди хода, ученик молчит ≥3 с), длина урока в промпте плана («не менее 60 минут, укажи минуты»),
  ЗАПАС целей, гвард прощания → «УРОК ЕЩЁ ИДЁТ» (не раньше 2-й минуты, кулдаун 1,5 мин).
  До планового конца прощание урок **не** закрывает; закрывает только в овертайме, строгим регэкспом
  по хвосту хода (80 знаков). В окне рекапа — «спроси, хочет ли продолжить, не назначай встречу».
  После «дрилл завершён» добавлено «это не конец урока».
- **Модель ведёт свой дрилл вместо системного.** Главная находка 07–08.09, подтверждена логом 70-минутной
  «удачной» симуляции (дрилл 7/7). Стимул 1 приходил вместе с планом, Хава начинала «дрилл» ещё в разминке,
  после «Верно» давала **свой** стимул, и машина засчитывала ответы на чужие вопросы. Evidence, мастерство
  и темп мерили чужой диалог. Лечение:
  - дрилл АКТИВЕН, только когда в речи учителя прозвучала база или ученик ответил на текущий стимул;
  - если ответ не совпадает с ожидаемым ни по одному слову (`token_overlap < 0.5`) → `resync`
    («не на этот стимул, тот же ещё раз»), кап `DRILL_RESYNC_MAX` (2 → 3);
  - если учитель сам сказал «надо <ожидаемое>», стимул подтверждён;
  - ответ без вердикта → один запрос `no_verdict`;
  - в первом ходе: «начни, когда по плану дойдёшь до цели дня, не сейчас; после каждого вердикта остановись».
- Парсер вердикта: «Неправильно. Надо …» не распознавался вовсе (дрилл замирал), а «почти верно»
  засчитывалось как ВЕРНО. Регэкспы: `(?<!не)верно`, + «правильно/отлично/молодец/מצוין».
- Модель «прощает» подмену одной буквы как опечатку — это её педагогическое решение, поэтому приёмку
  надо делать по агрегату.
- Модель рвёт свой же формат строк: у одной темы ни одна цель не прошла `clean` (меньше 2 примеров),
  и тема **молча** ушла в фолбэк. Лечение: логировать причину и повторить тему один раз в конце очереди.

## 3. Звук, микрофон, устройства, VPN (механизмы)

**Частоты и буферы.** Вход 16 кГц PCM16 mono, чанк 640 сэмплов (40 мс). Выход 24 кГц. Микрофон —
очередь drop-oldest (maxsize 50): если сеть отстала, модели уходит свежий звук, а не задержка на секунды.
Между сессиями очередь **сливается** (`drain`), иначе в новую сессию уедет старый звук. Динамик:
джиттер-буфер 200 мс на старте хода, дальше куски только склеиваются (иначе underrun);
`busy_until = конец + 1,0 с`, после записи хвост 0,6 с. На `Interrupted` буфер сбрасывается (`cut`).
Ресемплинга в динамике нет — на чужую частоту одно предупреждение.

**Windows/PortAudio.** Отмена во время `stream.write` в другом потоке роняет PortAudio: нужен shield,
дождаться выхода, `abort()` на умершем устройстве. `sounddevice` импортируется только внутри `start()`,
чтобы тесты шли без звуковой карты.

**Выбор устройства не доходил до звука** (`MicSource()`/`Speaker()` без `device=`), в том числе в мастере.
Отказ микрофона или динамика уходил только в `log.warning`: ученик сидел перед «идущим уроком» в тишине.
Теперь выводится видимая подсказка (MIC_HELP: разрешения Windows, выбор устройства, «пока можно писать
текстом»; SPEAKER_HELP). Индикатор говорил «слушаю вас» при выключенном микрофоне.

**Уровни.** Громкость микрофона гарнитуры стояла на 88 %, речь давала RMS 50–300, и детектор был слеп.
Подняли до 100 % (+30 дБ) через pycaw. Замер loopback: шумовой пол 90–235 < порог `HW_VOICE_RMS=500` <
речь 500–2700. Есть ли речь — решается **по уровню, а не по длине байтов**: 8 с тишины — много байтов,
но не речь, и отдавать её судье нельзя, она помечается «речи нет». Мастер: VU-проверка 3 с с порогом
`max_rms ≥ 300`, без неё «Дальше» заблокирована. Полоска VU в мастере не двигалась, потому что
`audio_level` шёл только в уроке.

**Эхо.** AEC нет, наушники обязательны. Есть переключатель в подвале урока: «в наушниках (можно
перебивать) / без наушников (по очереди)». Режим без наушников — полудуплекс `MUTE_MIC_WHILE_SPEAKING`
(речь ученика поверх учителя теряется). Ручка стояла в окне настроек, но её **никто не читал** — позже
подключили. Модели «чей голос» не объяснить: Live получает один поток без меток. План AEC: NLMS блоками
по 40 мс на numpy, 4096 отводов (~256 мс хвоста), опорный сигнал — то, что проиграл динамик (24→16 кГц,
кольцевой буфер со временем воспроизведения), детектор двойного разговора, затем остаточное подавление.
Приёмка: ERLE ≥ 20 дБ на ПК владельца и 10-минутный урок без самоперебиваний. **Ни один замер не сделан.**
Для оценки уже есть счётчик `interruptions` (сколько раз VAD перебил учителя).

**Запись занятия.** Один WAV на прогон, 24 кГц, обе стороны на **одной шкале по часам от начала урока**
(паузы слышны паузами). Внутри реплики куски идут подряд: динамик получает звук пачкой раньше, чем он
прозвучит. Перекрытие складывается с клиппингом. Запись потоковая, заголовок обновляется при каждом
сбросе, так что после падения файл открывается. ~170 МБ/час, потолок 180 мин. Ошибки записи **гасятся
внутри**: урок важнее записи. Проверка качества — RMS записи: 1661 при её речи против 27 в тишине.
Грабли: звук и тексты одного занятия ложились в **две папки**, потому что уровень считали двумя
способами. Починили связью: папку выбирает запись, архив кладёт тексты туда же.

**Сеть/VPN** (без адресов). Каскад: REST-проба → прямой путь → Tailscale exit node (выбор самого быстрого
узла; смена при ≥2 **аномальных** обрывах за 300 с, кулдаун 600 с, только между сессиями) → свой
Xray VLESS+Reality (локальный HTTP-прокси; переменные `HTTPS_PROXY`/`WSS_PROXY` читаются библиотеками
при каждом новом соединении) → резервный прокси из `.env`. Перед каждым connect **проверять, жив ли
процесс Xray** (`ensure_path`): метод перенесли из 1.0, но никто его не вызывал, и смерть xray давала
бесконечные обрывы. Бэкофф экспоненциальный с джиттером до 30 с. После 10 неудач подряд или 180 с без
сессии — состояние offline, повтор каждые 30 с без участия пользователя. Баннер качества связи даёт
человеческий совет. **WebView2 не читает HTTPS_PROXY** (веб-контент окна мимо VPN). **Хранилище
сертификатов Windows** для Викисклада отдавало «certificate has expired», через certifi всё работало;
Tavily при этом работал, поэтому проблему долго не видели.

**Сборка/Windows (коротко).** PowerShell 5.1 без BOM читает кириллицу как cp1251, и скрипт раскладки
не парсился (сломался именно в том коммите, который добавлял файл в раскладку). `.bat` нужен в CRLF.
`Path.write_text` переводит файлы в CRLF, поэтому файлы правят байтами. Печать «▶» в cp1251-лог
роняла прогон.

## 5. Метрики, тесты, харнесс

**5.1 Слои проверки (на 12–13.09):** pytest **1232** (4 skipped, без сети); мутационные проверки гвардов
**238/238**; самотест окна **198/198** в настоящем WebView2; `--selfcheck` из dist **два круга подряд**
(9 шагов, ~94 с: файлы, ключи, сеть, модель, силлабус, план **с непустым дриллом — иначе шаг падает**,
набор домашки, тест уровня, голос). Selfcheck работает на временной папке `lessons`. Ограничение
признано честно: selfcheck **не ведёт урок и не судит ответы**.

**5.2 Мутационные проверки** (`tools/mutate_guards.py` + `tools/mutations_data.py`). Для каждого гварда
записано, какая однострочная правка его ломает и какой тест обязан упасть. «ПЕРЕЖИЛА» = гвард потерян;
«ШАБЛОН?» = код ушёл, мутацию надо обновить. Правило: **добавил гвард — добавь мутацию**. Грабли самого
инструмента:
- без таймаута зависший pytest вешал прогон, а убитый прогон оставлял файл **мутированным** →
  `NODE_TIMEOUT_S=180`, статус ЗАВИСЛА;
- мутации переписывали файлы в LF → правка байтами;
- предпроверка образцов: мутация, чей образец не найден, молча ничего не стережёт → прогон не начинается;
- параллельно с мутациями pytest и правки запрещены;
- найдена **эквивалентная** мутация (V3): порядок слоёв ничего не защищал. Её перенацелили, а по ходу
  нашли настоящую дыру (3801 токен словаря не находился).

**5.3 Моки — по контракту.** Самотест окна был 132/132 зелёным при **неработающих настройках**: моки
описывали формы событий, которых движок не шлёт (плоский `get_settings`, `drill.results`). Подставной
план в тесте selfcheck имел выдуманное поле `items`, и шаг «план» хвалил **план без дрилла** («дрилл:
0 стимулов» ✓). Правило: подставка = настоящий тип или форма из кода движка. Тесты писали в настоящий
архив на H: → фикстура `autouse` на весь прогон + тест-гвард «архив не тронут».

**5.4 Тотальная проверка** («гниение памяти»). Источник — прямые цитаты владельца. Для каждого требования
найти место в коде и классифицировать: исполнено / только в промпте / гвард не срабатывает /
противоречит коду. Особое внимание — местам, где **промпт и код говорят об одном**, потому что
расхождение там незаметно. Плюс механическая сверка «ручка config → доходит ли до потребителя»
(grep). Так нашлись `TEMPO_FAST_S`, `MUTE_MIC_WHILE_SPEAKING`, копии констант в модулях и дефолты,
связанные при импорте. Плюс сверка 1.0 ↔ 2.0 метод за методом (принцип «эх раз» остался только в 1.0),
каждая строка UI против кода и каждый докстринг против тела функции. Проходы раздавали агентам, **каждую
находку проверяли сами**. Три волны нашли 9 + 20 + 13 находок: дрилл мерил чужой диалог; обещание
«вернёмся через 2 задания» не исполнялось никогда; ревизия силлабуса не вызывалась никем; тренировочные
карточки SRS вечно «новые»; два экземпляра «устаревшая копия learner затирает результат»; `curriculum._save`
возвращал `or True`.

**5.5 Как мерили качество урока** (`meta.json`/`_metrics.jsonl` каждого прогона):
- доля речи `floor_ratio` ученика ≥ 0,45 (1:1, учитель 30–50 %); `avg_student_words` растёт от урока
  к уроку; реплика учителя ≤ ~75 токенов (2–3 предложения). Уроки с письмом (`written_turns`) сравнивать
  с устными нельзя;
- `service_echoes`, `written_echoes`, `board_calls`, `interruptions`, `drops`/`reconnects`, `ended_by`
  (farewell/idle/time/quit), `farewell_nudges`, `time_hints`, `overtime_min`;
- дрилл: `drill_active`, `drill_resyncs`, `drill_no_verdict`, `drill_alts`/`varied`/`alt_dropped`
  (`alts` — детектор гниения: перестала писать ALT → ноль);
- `words_seen`, покрытие словаря; финализация N/N шагов; EXIT=0, tracebacks 0.
- Гейт мастерства: «освоено» не засчитывается без ≥3 попыток **без образца**; ответ после
  подсказки или объяснения не считается и темп его не мерится.
- Доска не показывает ожидаемую форму, пока её ещё спросят (`is_pending`), иначе «ещё раз» превращается
  в чтение с доски. ALT-контекст снимается, если учитель произнёс его до возврата.
- Анти-подхалимаж судьи (loopback): заведомо неверная фраза → 20–28 баллов, верная → 89–100,
  «одно слово не то» → 78–83 при пороге 80 (серая зона, решают живые фразы).
- Хава сама оценила проект (7/10). Её предложения приняли **с компенсацией в харнессе**, чтобы учёт
  не сломался.

**5.6 «Робот находит то, чего не видят тесты».** Пять ошибок нашли только живые прогоны без ученика:
две папки архива на одно занятие; тесты пишут в боевой архив; клуб ставит новичку гимель; настройки
не доходят до урока до перезапуска; сертификаты Windows. Короткие скрипты-прогоны (урок, клуб, файл)
гонять после каждой крупной правки.

## 7. Чек-лист для italo-tutor: что нам грозит и как сделать сразу правильно

Сверено с текущим кодом `italo-tutor/lib`. Многое уже перенесено: `SessionKeeper` (goAway-рефреш,
отложенный брифинг, MuteHeal ≤2), `service.dart` (префикс, первый ход, СТИМУЛ/СМЕНИ ПОДХОД/СТОП,
`looksLikeServiceEcho`), `AnswerTiming` (темп от конца звука, по RMS, а не по транскрипту), `LessonClock`
(60/120, гвард прощания, «продолжаем?» через 4 мин), гейт мастерства, OneShot через транскрипт, без
`thinkingConfig`. Ниже — то, что **ещё грозит**, по приоритету.

### P0 — ошибки, которые сработают на первом же уроке
1. **Регион-блок уходит в «модель недоступна».** `lib/core/gemini/gemini_live_client.dart`,
   `LiveSetupRejected.looksModelUnavailable` ловит `not supported`. Причина 1007 от Google —
   «User location is **not supported**…», значит без VPN 3.1 помечается недоступной, переключаемся на 3.8,
   та тоже падает → `LiveModelsUnavailable` вместо «включите VPN». Кроме того,
   `_unavailableModels` держит модель до перезапуска программы. Исправление: сначала проверять
   `location` / код 1007 / FAILED_PRECONDITION → отдельное исключение «регион» (→ VPN,
   `lib/core/vpn/vpn_service.dart`). В `paolo_connector.dart` регион не должен штрафовать ни модель, ни ключ.
   Отдельно: 1007 на TEXT-модальность, на media-кадры и на PDF — это наш баг, а не модель.
2. **Push-to-talk без конца речи.** `live_session_screen.dart` `_stopRecording()` просто останавливает
   поток. Серверный VAD при оборванном потоке **не видит конца речи** (у Хавы четыре реплики склеились
   в одну). При отпускании кнопки слать `{"realtimeInput":{"audioStreamEnd":true}}` и/или хвост тишины
   ≥ `silenceDurationMs` + ~300 мс нулями (как `with_silence_tail`). Проверить живьём на 3.1 и 3.8.
3. **Нет `realtimeInputConfig` и `contextWindowCompression`** в `setup` (`gemini_live_client.dart` →
   `connect`). Добавить `realtimeInputConfig.automaticActivityDetection = {endOfSpeechSensitivity:
   END_SENSITIVITY_LOW, silenceDurationMs: 2500}` (настройка «пауза после реплики»; при push-to-talk
   значение можно меньше, но решать замером) и `contextWindowCompression: {slidingWindow: {}}`.
   Без компрессии часовой урок на одном хендле рискует упереться в лимит контекста.
4. **Вердикт разбирается из заглушённого эха.** `live_session_screen.dart` `LiveTurnComplete` →
   `_onPaoloTurn(_turn.toString())` вызывается и тогда, когда `_muted == true`. `parseVerdict`
   (`lib/features/course/domain/drill_runner.dart`) увидит «Верно…» или «ожидается «…»» из нашего же
   служебного текста — ровно те пять ложных «верно» у Хавы. Нужно резать текст хода от маркера
   `(служебное` (и `(ученица написала`) до разбора, как `strip_service_echo`. Если остаток пуст — вердикта нет.
5. **Неизвестный tool call остаётся без ответа** → Паоло замолкает (вызов у 3.1 синхронный).
   `_onEvent` → `default: break`. Отвечать всегда: `sendToolResponse(id, name, {'error':'unknown tool'})`.
   Будущие долгие инструменты (картинки, поиск) — ответ сразу, работа в фоне.
6. **Нет дедлайна у goAway-рефреша.** `_tryRefresh` ждёт паузы бесконечно. Если ученица говорит или
   Паоло длинно объясняет, сервер закроет с 1008 через ~50 с после goAway. Нужно: парсить `timeLeft`
   («50s»), закрывать сразу при простое, иначе после хода, но **не позже** `timeLeft − ~10 с`.
   Не рефрешить сразу после отправки служебного сообщения (`SessionKeeper.canRefreshNow`).
7. **Полный брифинг после успешного resume.** `_onDropped()` зовёт `_keeper.onDropped(_briefing())` ДО
   попытки по хендлу; если `resumed == true`, длинный брифинг всё равно уйдёт со следующей репликой.
   У Хавы это давало эхо, модель читала план вслух. После resume — короткий брифинг («связь обновлена —
   продолжай» + время + дрилл) или никакого; полный — только при `resumed == false`.

### P1 — надёжность часового урока
8. **Реконнект без классификации и бэкоффа.** `_onDropped` делает одну попытку по хендлу, одну без
   хендла и переходит в error. Перенести таблицу `NetPath.on_drop`: коды закрытия `closeCode/closeReason`
   из `IOWebSocketChannel` (сейчас используются только до setupComplete) → region / quota (ротация ключа
   в `KeyManager`, без задержки) / auth / net (бэкофф с джиттером до 30 с) / clean-close (узел VPN не
   менять) / resume_rejected (сброс хендла). После 10 неудач или 180 с — состояние «нет связи» с автоповтором
   каждые 30 с. Манёвры VPN — **только между сессиями**. Перед каждым connect проверять, жив ли
   xray-процесс (`vpn_service.dart`).
9. **OneShot хрупкий.** `lib/features/course/data/paolo_model.dart` `LivePaoloModel.ask`: при закрытии
   сокета до `turnComplete` ждёт весь таймаут 120 с (`onDone` не завершает `done`); нет продолжения
   частичного ответа, нет повтора немого/пустого хода, нет очереди. Перенести: `Semaphore(1)` на
   OneShot'ы, раунды «продолжи РОВНО с этого места» (до 3, раунд 75 с, дедлайн 120 с), повтор пустого
   ответа, лог `ok|partial|fail`. OneShot'ы гнать на **втором ключе**, чтобы не делить квоту урока
   (`lib/core/keys/key_manager.dart`).
10. **Служебные отметки посреди речи.** `_onTick` раз в 20 с шлёт `nudges()`, если нет реконнекта, но не
    проверяет, говорит ли Паоло. Текст в `realtimeInput` посреди его хода может перебить или сбить ход.
    Как у Хавы: только в простое (Паоло не говорит — `_voice.speaking == false`, буфер хода пуст —
    и ученица молчит ≥3 с); иначе в очередь, как `_deferred`.
11. **Парсер вердикта.** `parseVerdict` не узнаёт «Неправильно…/Нет, надо…/Non è corretto…» без формулы
    «Ошибка (тип)» → дрилл стоит молча. Добавить явный `VerdictWrong` и один служебный запрос
    «назови вердикт» (`no_verdict`) на стимул. «Верно» проверять как `(?<!не)верно`, «почти верно» ≠ верно.
12. **Дрилл мерит чужой диалог.** Сейчас дрилл стартует по `start_drill` (это лучше, чем у Хавы), но
    ответ на стимул никак не сверяется. Перенести гейт: если ответ ученицы не пересекается по словам
    с ожидаемым (`token_overlap < 0.5`) и Паоло не сказал «надо <ожидаемое>» → resync (тот же стимул,
    кап 3). Повтор базы — не ответ. Код: `drill_runner.dart`, `_onPaoloTurn`.
13. **Эхо пометки письма.** В `service.dart` добавить снятие «(ученица написала, не сказала)» в начале
    хода (звук не глушить, ход разбирать) и запрет в промпте начинать ответ с неё. Метрика `written_echoes`.
14. **Картинки/файлы ученицы** (когда дойдём): только `clientContent.turns` с `inlineData` и
    `turnComplete:true`; `realtimeInput.media` и PDF вложением → 1007; PDF — текстом.

### P2 — звук, голос, UX
15. **Голос Algenib.** По опыту Хавы 3.1 игнорирует `voiceName`. Пробы владельца в `~/paolo_audio/male/`
    говорят, что у нас он работает. Проверить отдельно на 3.1 и 3.8 и **держать описание голоса и
    в system prompt** (`lib/core/gemini/paolo_persona.dart`), чтобы при фолбэке голос не «съехал».
16. **Отказ микрофона и динамика видимым сообщением** (не только SnackBar при отсутствии разрешения):
    выбранное устройство не открылось / нет звука на выходе → подсказка + «пока можно писать».
    Проверить, что выбранный выход реально используется в `_voice`. VU-проверка с порогом в мастере.
    Проверка наушников — голосом Паоло, без тестового тона.
17. **Режим без наушников.** Push-to-talk — это по сути полудуплекс (эхо почти не грозит), но если
    появится «открытый микрофон», нужен переключатель «в наушниках / без» и глушение микрофона, пока
    Паоло говорит. AEC — только с замером ERLE.
18. **Запись занятия** (P1 для качества): обе стороны на одной шкале, потоковый WAV с обновлением
    заголовка, ошибки записи не роняют урок; одна папка на занятие (путь выбирает запись). Без записи
    ударения в речи Паоло не проверить.
19. **TLS на Linux/флешке**: у Хавы хранилище сертификатов Windows дало «expired». Для USB-сборки под Linux
    проверить, что `HttpClient` видит CA (или везти свой bundle), особенно через прокси Xray.

### P3 — дисциплина проверки (перенять сразу)
20. Для каждого гварда из списка выше — тест на `FakePaoloModel`/фейковом WebSocket
    (`test/paolo_connector_test.dart`, `session_keeper_test.dart`, `drill_runner_test.dart`,
    `lesson_clock_test.dart`) **плюс мутация**: однострочная поломка, которую тест обязан поймать.
    Регион 1007 ≠ модель недоступна; вердикт из эха не засчитывается; неизвестный tool получает ответ;
    goAway закрывается до `timeLeft`; брифинг после resume короткий.
21. Моки — по реальным формам сообщений Live (JSON из живого лога), а не «как удобно».
22. Каждая настройка → grep до потребителя. Каждая строка UI, которая утверждает что-то о поведении,
